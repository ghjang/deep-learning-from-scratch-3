## 0. 한 장 요약 — fill_grad 하나가 차수를 결정

> **fill_grad는 도구가 하나일 뿐 — 어떤 그래프를 주느냐가 차수를 결정한다.**
> - `fill_grad(y)` → 1층(원본)을 순회 → **1계 미분** (f')
> - `fill_grad(out2)` → 2층(1계 미분식)을 순회 → out2를 미분 → out2가 f'였으니 **2계 미분** (f'')
> - `fill_grad(gxx)` → 3계... (tanh 폭증의 길)

"2계 미분 기능"을 따로 구현한 게 아니라, **"미분 = 그래프 소유 계산"이라는 성질 하나가 차수를 무한대로 열어준 것.** 노트 30 3단 논법(미분은 계산이다 → 계산은 그래프를 남긴다 → 남은 그래프는 재미분 가능)의 실체. (브로 발견, 2026-08-26)

<a id="원본과미분"></a>
## 1. 원본 그래프와 미분의 관계 — 브로 최종 정리 (2026-08-26)

> 브로: *"최초 순전파가 만드는 그래프는 미분 이전의 원본 계산 그래프. 1차 역전파는 그 오리지널 그래프를 통해 1계 미분을 계산. 이때 create_graph=True로 진행하면 완료 시점에 '역전파 계산 자체의 그래프' = 1계 미분 계산 식이 존재. 여기서 2차 역전파를 때리면 1계 미분 식을 다시 1계 미분하는 것 — 결과적으로 원본에 대한 2계 미분."*

전부 정확. 수식 대응 (**x = Variable(np.array(3.0))** — 모든 단계의 공통 출발점 (다이어그램 04~06은 x=2 사용 — 노트에서만 혼동 방지를 위해 3으로 변경: x=2일 때 y=4와 f'(2)=4가 같아져 순전파 값인지 미분 값인지 헷갈리기 때문)):

| 단계 | 실행 코드 | 결과 (.data) | x.grad | x.grad.creator | x의 역할 |
|---|---|---|---|---|---|
| 순전파 | `y = square(x)` | **y.data = 9.0** (= 3²) | None | — | **입력 제공자**: x.data=3.0을 함수에 넣어줌 |
| 1차 역전파 (create_graph=True) | `fill_grad(y, create_graph=True)` | **x.grad.data = 6.0** (= f'(3) = 2·3) | Variable(6.0) = out2 ("2x" 식) | Mul | **grad 수령자** + 2층에도 리프로 참여 |
| 2차 역전파 (create_graph=False) | `out2 = x.grad; x.clear_grad(); fill_grad(out2)` | **x.grad.data = 2.0** (= f''(3)) | Variable(2.0) | None (lean) | **grad 수령자** (f''값 받음) |
| 2차 역전파 (create_graph=True) | `out2 = x.grad; x.clear_grad(); fill_grad(out2, create_graph=True)` | **x.grad.data = 2.0** (같은 값!) | Variable(2.0) — 값 동일 | Mul (3층 보유 → 3차 가능) | 동일 + 3층에도 리프 참여 |

★ 각 단계의 **시작점 = 이전 단계의 최종 출력** — 순전파의 y가 1차의 시작점, 1차의 out2가 2차의 시작점. **fill_grad에 넣는 Variable이 순회할 층을 결정** (§0의 표 버전).

★ out2의 값: `out2.data = 6.0` — "2x라는 식"이 x=3에서 평가된 Variable. data에 6.0 + creator에 Mul (계산 구조 보존).

★ x의 이동 경로: 순전파의 입력(x.data=3.0 제공) → 1차에서 grad 수령(out2 대입) + 2층 리프로도 참여(미분식 2x가 x를 참조) → 2차에서 다시 grad 수령(f''값) → **모든 층에 등장하는 공유 리프**.

★ v2에서 x.grad는 **항상 Variable** (create_graph 무관) — 차이는 **creator의 유무**:
- creator 있음 = 그래프가 붙은 Variable("식") → 다음 차수 미분 가능
- creator 없음 = lean한 Variable("값") → 재미분 불가 (f''=2는 상수이므로 더 미분해도 x로 가는 간선 없음)
- ★ **2차 역전파의 결과값은 create_graph 여부와 무관하게 항상 2.0** — create_graph=True는 "그 결과에 3층 그래프를 붙여 3차를 예약"할 뿐, 값 자체를 바꾸지 않음

★ x.grad 슬롯의 재활용 패턴: 매 차수마다 clear_grad로 비우고 다음 결과를 받음. 들어가는 건 항상 Variable이며, create_graph=True이면 그래프가 붙은 채로 들어감.

★ 핵심: **1차 역전파는 eval까지 완료하는 실행이었다** — 그래프만 만든 게 아니라 값(out2.data=6.0)까지 계산. 노트 33 "모든 실행은 그래프를 낳는다"의 반대 명제 — 그래프를 낳은 그 실행은 평가였다. (브로 발견)

<a id="이중정체"></a>
## 2. out2의 이중 정체 (책 표기: gx)

> 브로: *"백프랩의 일종의 순전파 아닌가? 근데 out2는 x의 grad잖아? grad가 Variable이란 소리고?"*

| 관점 | out2의 정체 |
|---|---|
| **x 입장** | x.grad 슬롯에 저장된 것 (1차 미분 결과) |
| **2층 그래프 입장** | 2층의 **최종 출력 Variable** — 1층에서 y가 하던 역할을 그대로 이어받음 |

- **"1차 역전파 = 2층의 순전파"** — 1차 역전파를 실행하는 순간 그 계산 자체가 2층 그래프를 순전파한 것.
- `out2 = x.grad`는 "x의 grad 슬롯에서 Variable을 꺼내 out2라는 이름으로 참조하겠다"는 사용자 코드 — 이 순간 사용자 참조가 생겨 2층 그래프 생존 보장.
- out2와 x의 관계: **직접 참조 아님** — `out2.creator → Mul(2) → t1 → Mul(1) → x`로 creator 사슬을 타고만 닿음.

### ★★ 순환은 존재한다 — 그러나 문제가 아니다 (브로 발견, 2026-08-28)

> 브로: *"out2와 x가 그래프에서 순환 참조처럼 보이는데, 문제는 발생하지 않는 건가?"*

브로 눈이 정확함 — 참조 사슬을 추적하면 실제 사이클이 존재:

```
x.grad = out2          (x가 out2를 강하게 참조)
out2.creator = Mul(2)
Mul(2).inputs = (t1, up0)
t1.creator = Mul(1)
Mul(1).inputs = (x, c2)   ← x (도착!)
```

→ **`x → out2 → Mul(2) → t1 → Mul(1) → x` 순환 발생.**

이 순환이 생기는 시점: 순전파 시점엔 없음 (x는 리프, creator=None). **1차 역전파가 `x.grad = out2`를 대입하는 순간** 생김 — "미분 결과를 입력 변수의 속성에 저장한다"(§7)는 설계가 구조적으로 순환을 만드는 것.

**왜 문제가 안 되나 — 3층위 정리**:

| | 이 순환 (x ↔ 2층) | step17의 순환 (Variable ↔ Function) |
|---|---|---|
| 사이클 | x → grad → out2 → creator 사슬 → x | Variable → creator → Function → output → Variable |
| 문제 | 사용자가 x를 버리면 순환 감지 GC가 처리 | 사용자가 output을 버려도 Function이 강하게 붙잡아 **즉시 회수 안 됨** |
| 해결 | 불필요 — Python 순환 감지 GC가 커버 | **Function.output을 weakref로** — 즉시 회수 가능하게 |

★ **step17 weakref의 정확한 위상** (브로 재확인): 순환 감지 GC는 step17의 순환도 처리할 수 있음 — weakref는 "순환을 없애는 것"이 아니라 **"사용자가 버린 output을 GC 주기와 무관하게 즉시 회수 가능하게"** 만든 것. 즉 weakref는 순환 제거가 아니라 **회수 시점의 개선** — 브로: *"이 경우에도 사실 순환감지 GC가 커버한다는 건데, 다만 '즉시 회수'를 의도적으로 표현한 것"*. 정확한 재해석.

★ 정리: **"미분 결과를 입력 변수의 속성에 저장한다"(§7)는 설계가 구조적으로 순환을 만들지만, 그 순환은 Python GC의 관리 범위 안** — 설계의 알려진 특성이지 버그가 아님. (탐구 노트 22의 GC 이론과 연결 — 순환 감지 GC는 참조 카운팅만으로 낚지 못하는 사이클을 별도 알고리즘으로 수거)

### ★ cleargrad의 부차 효과 — 순환 끊기 (책이 다루지 않는 층위, 2026-08-28 브로 발견)

책의 최적화 루프(step28, 33, 34, 35)에서 매 iteration마다 `x.cleargrad()`를 호출 — 책은 이걸 **누적 방지**(step14) 목적으로만 설명. 하지만 실은 이중 효과:

| 효과 | 설명 | 출처 |
|---|---|---|
| **① 누적 방지** (명시적) | grad 슬롯을 비워서 다음 backward가 이전 것과 더해지지 않게 | 책 step14 — 명시적 목적 |
| **② 순환 끊기** (부차적) | `x.grad = None` → x가 이전 out2를 더 이상 참조 안 함 → **순환의 x→out2 간선이 끊어짐** | ★ 브로 발견 — 책 미언급 |

- 책의 step17 "순환 참조"는 Variable↔Function 간의 **다른 순환** — x↔2층 순환과 cleargrad의 부차 효과는 책 어디에도 없음
- 루프에서 `y = f(x)`를 다시 실행하는 것 자체도 이전 iteration의 y가 덮어써져 자연 GC되는 정리 효과 (별도 조치 없이 파이썬 스코프가 하는 일)
- ★ **루프 탈출 시 마지막 grad는 남아있음** (브로 질문, 2026-08-28): 루프 안의 cleargrad는 "이전 것을 지우는" 것이니 루프를 나가면 마지막 iteration의 x.grad가 그래프를 계속 붙잡고 있음. 상황별 판단: 스크립트형(책 예시)이면 프로세스 종료로 전부 회수되니 불필요 / 다음 루프가 있으면 첫머리 cleargrad가 자연 정리 / 메모리 민감 환경이면 루프 후 한 번 더 호출하는 클린업 권장. PyTorch의 `optimizer.zero_grad()`도 배치 시작마다 호출하지 끝에서 하지 않는 것과 같은 패턴.
- **rezero에 이미 전부 갖춰져 있음** — clear_grad (누적+순환), no_grad (그래프 안 만듦), retain_grad=False (중간 자동 버림). 추가로 만들 것 없음.

## 3. grad 슬롯의 생애 — 중간의 자동 처분, 리프의 면책

> 브로: *"중간 순회 시 중간 변수의 grad는 전부 초기화되는데, 리프 단은 순회 과정에서 초기화 부분이 없다?"*

코드 구조 (`fill_grad`의 `output.grad = None`은 **output에만** 적용):

| | 중간 변수 grad | 리프 grad |
|---|---|---|
| 정체 | 소비 끝난 **임시값** | 역전파의 **최종 산물** |
| 자동 처분 | O (output.grad=None) | **X — 자동 초기화 경로 자체가 없음** |
| 비우는 주체 | 프레임워크 | 사용자 (clear_grad) |

- 리프가 어떤 f의 output이 **될 수 없는 위치** (inputs 쪽에만 존재)라 루프가 못 건드림.
- clear_grad를 x에만 하는 이유: 2차 결과를 받을 슬롯이 x.grad 하나 (y.grad는 이미 버려짐, 중간들도 버려짐) + 안 비우면 누적 오염 (`out2 + f''`).
- 리프/중간 판정은 **그래프 구조 기준**(creator 있느냐)이지 사용자 참조 여부가 아님 — 중간 변수를 사용자가 들고 있어도 retain_grad=False면 버려짐.
- create_graph=True여도 중간 슬롯의 값은 버려짐 — "값은 버려도 식은 2층에 남는다".

## 4. 신생 vs 재참조 — 미분식이 명단을 정한다

> 브로: *"미분 결과가 생성하는 함수는 새로운 함수 객체가 맞나? 변수 부분은 재참조되는 부분이 있다?"*

- **함수 객체는 전부 신생** — `mul(x, 2)` 호출마다 `Mul()` 새 인스턴스.
- y=x²의 2층 구성원: 옛 객체 재등장은 **x 하나**, 나머지(c2, up0, t1, out2, Mul들) 전부 이번 역전파에서 신생.
- **어떤 옛 변수가 재등장하나는 미분식 성분(노트 32 유형 지도)이 결정**:

| 도함수 유형 | 재등장하는 옛 변수 |
|---|---|
| ① 상수형 (Add) | 없음 |
| ② 입력형 (Square: 2x) | 자기 입력 x |
| ③ 형제 의존 (Mul: x₁) | 형제 입력들 |
| ④ 출력형 (Tanh 재사용: 1-y·y) | **forward 출력 y** |

- ★ 합성 함수가 오면 **중간 출력도 재등장** — sin(x²)의 미분 cos(x²)·2x에서 cos가 참조하는 건 x가 아니라 1층 중간 출력(x² Variable). → 후보 12 실험 예정.
- 브로 초기 질문 "x만 재활용?"의 답: y=x² 예시가 입력형이라 x만 보였을 뿐 — 일반 규칙은 "직전 층을 구성하는 부품 전부가 재등장 후보, 명단은 미분식이 정함".

<a id="up0생존"></a>
## 5. up0의 생존 조건 (책 표기: gy)

- up0 = Variable(ones_like)는 fill_grad 내부에서 태어나 **사용자 참조 없음**.
- create_graph=True → 2층이 참조해 생존 (Mul(2).inputs의 강한 참조).
- False(기본) → 순회 계산 중에만 쓰이고, retain_grad=False면 y.grad에서조차 버려져 계산 후 GC.
- "상수 1조차 2층 그래프의 리프" (core.py 주석).

<a id="세가지"></a>
## 6. data · grad · output — 세 가지는 전부 다르다

> 브로: *"2층의 최종 출력 Variable의 output과 grad에 모두 값이 저장되는 상황인가?"*

out2 하나를 놓고 보면 (답: **저장은 data뿐**):

| 필드 | out2에서의 상태 | 비고 |
|---|---|---|
| **data** | 6.0 | ★ 유일한 값 저장 — 1차 역전파가 계산 |
| **grad** | None → 2차 때 씨앗 1 잠깐 → 버려짐 | out2도 누군가의 output이라 자동 처분 대상 |
| **output** | out2의 필드가 **아님** | `Mul(2).output = weakref(out2)` — 남이 나를 참조하는 관계 |

- "식을 소유"의 구현 = `creator != None` (+ 사슬로 전체 복원 가능).
- "식이 살아있다"의 구현 = creator→inputs 강한 참조 사슬이 그래프를 GC로부터 보호 (out2 하나로 2층 전체 생존).

표현 사전:

| 노트 표현 | 구현 |
|---|---|
| "식을 소유" | `creator != None` |
| "값을 소유" | `data`에 숫자 |
| "식이 살아있다" | 참조 사슬이 GC로부터 보호 중 |

<a id="대칭"></a>
## 7. 순방향 output / 역방향 grad — 대칭 구조

> 브로: *"순방향의 출력 변수는 output이고 역방향의 출력 변수는 grad란 게 이제야 감이 오면서 여전히 헷갈린다."*

| | 순전파 | 역전파 |
|---|---|---|
| 입력 | 리프들 (x) | **1** (씨앗, y에서 출발 — 곱셈 항등원) |
| 출력 | **y** (명시적 반환) | 리프들의 grad 필드에 **흘어져 기록** (반환 없음 — fill_grad는 None) |

- 역전파의 결과는 `local * upstream`로 **새 Variable**을 만들어 상대 함수의 **입력 변수 .grad 슬롯에 대입** — "출력의 저장 위치가 grad 필드"인 것.
- 이 대입은 **그래프 밖의 코드**(fill_grad의 배분 단계)가 수행 — 그래프가 아니라. (UML 04 리뷰에서 확정)
- 순전파 "여러 입력 → 하나의 출력", 역전파 "하나의 씨앗 → 여러 리프로 흩어짐" — 뒤집힌 거울.
- ★★ **브로 발견** (2026-08-28): *"역전파의 결과는 결국 입력변수 자체에 있다!"* — Variable 하나가 **순전파의 입력(x.data=3.0)과 역전파의 출력(x.grad=6.0)을 동시에 들고 있는 구조**. 이 설계의 이유: 파라미터가 수백만 개일 때 리턴값으로는 못 돌려주니까 — 각자 자기 grad 슬롯에 채워지면 `x.grad`, `W.grad` 한 줄로 접근. 순전파는 출력이 1개(y 리턴)라 리턴 구조가 되지만, 역전파는 출력이 여러 개(모든 리프의 grad)라 **속성 저장이 유일한 선택**.
  - ★ **output vs grad — 저장 주체의 비대칭** (브로 발견, 2026-08-28):
    - `output`은 **Function의 속성** — 함수가 자기 결과를 가리킴. "내가 무엇을 만들었나" (함수의 이야기)
    - `grad`는 **Variable의 속성** — 변수가 자기 미분값을 보유. "나는 얼마나 민감한가" (변수의 이야기)
    - 각자 자기 이야기를 자기 속에 보관 — 브로: *"순전파 결과는 함수가 기억, 역전파 결과는 변수가 보유 — 절묘한 배치 같으면서 헷갈린다"*
    - 브로가 개념적으로 쓴 "순방향 출력/역방향 출력"이 실제 코드 속성 이름과 우연히 일치 — 직관이 구조를 먼저 잡은 사례
  - ★ **Variable 안에 Variable — 재귀적 중첩 구조** (브로 발견, 2026-08-28):
    - `Variable.data` = ndarray (값) / `Variable.grad` = **Variable** (미분 결과)
    - 즉 **같은 타입의 객체가 자기 속성으로 자기 타입을 들고 있음** — 재귀적 구조
    - v1에서는 grad가 ndarray라 이 중첩이 없었음 — v2의 `grad=Variable`이 만든 신구조
    - 이 중첩이 **n차 미분을 가능하게 하는 물리적 기반**: grad가 Variable이므로 또 그래프를 가질 수 있고, 그 grad도 Variable이므로 또 미분 가능 — "미분의 미분의 미분..."이 무한히 열리는 것
    - `x.grad.grad` = 2차 미분 결과의 미분 (3차용) — 러시아 인형처럼 각 차수마다 Variable이 중첩

<a id="다변수위계"></a>
## 8. 다변수 × 고차 미분의 위계 — gradient → Hessian → 텐서 (브로 유도)

> 브로: *"1차 역전파 후 각 변수에 전달된 걸 모으면 그래디언트 → 2차 백프랍하면 헤시안? → 3차는 3D 모양의 무언가?"*

**1차 — gradient 벡터** (n개):

```python
# 입력 x, w → y = f(x, w)
fill_grad(y, create_graph=True)
# x.grad = ∂L/∂x (Variable, "식")
# w.grad = ∂L/∂w (Variable, "식")
# → 모으면 gradient: [∂L/∂x, ∂L/∂w] — 벡터
```

★ Define-by-Run + 리프별 grad 슬롯 = **자동 편미분 지원** (책이 명시 안 하지만 step13부터 이 구조).

**2차 — Hessian 행렬** (n²개): fill_grad에 "어느 변수의 1차 미분식"을 넣느냐가 Hessian의 **행**을 결정:

```python
fill_grad(x.grad)   # x 행: x.grad=∂²L/∂x², w.grad=∂²L/∂x∂w  ← 비대각도 나옴!
fill_grad(w.grad)   # w 행: x.grad=∂²L/∂w∂x, w.grad=∂²L/∂w²
# 총 fill_grad를 n번 돌려야 Hessian n×n 완성
```

**브로 발견**: *"fill_grad 한 번에 대각 + 비대각이 같이 나온다"* — fill_grad(x.grad)를 넣으면 그 그래프의 **모든 리프**에 결과가 흩어지므로 Hessian의 x 행 전체(대각+비대각)가 나오는 것.

**3차 — 텐서** (n³개): 브로 직관 *"3D 모양의 무언가?"* → 정확히 **3차 텐서** (3D 배열). T[i][j][k] = ∂³L/∂xᵢ∂xⱼ∂xₖ. 일반화: **n개 변수의 k차 미분 = n^k개 성분의 k차 텐서** — 다중선형대수(multilinear algebra)의 세계 (노트 35 §9 "수학 텐서 = 다중선형 사상"이 이 언어).

**크기 폭발과 실무**:

| 차수 | 크기 | 신경망 n=수백만 시 | 실무 |
|---|---|---|---|
| 1차 (gradient) | n 벡터 | 수백만 | ★ 압도적 (모든 딥러닝) |
| 2차 (Hessian) | n² 행렬 | 수조 — 물리적으로 불가능 | 간혹 (뉴턴법) |
| 3차 (텐서) | n³ 텐서 | 우주가 작음 | 없음 |

★ 실무 2차는 Hessian 행렬을 **만들지 않고** HVP (Hessian-Vector Product)만 계산 — 노트 34 "야코비안을 안 만들고 VJP만"과 **동일한 패턴**. L-BFGS는 gradient만으로 H 근사. → **"야코비안은 흐르지 않는다" → "Hessian도 흐르지 않는다"** — 같은 철학의 위계적 적용.

### ★ 출력이 여러 개? — dezero의 설계적 배제

> 브로: *"출력 여러 개는 애초에 지원하게 설계된 건가?"*

- **아니요** — dezero 자체가 출력 1개(스칼라)를 설계 전제로 함 (`assert len(ys) == 1`). 우리 v2 전제 4번은 이걸 문서화한 것.
- 출력이 여러 개면 씨앗(dy/dy=1) 자체가 모호해짐 — "어느 출력의 1인가?"
- 실전 패턴: **loss 함수로 요약해서 스칼라 1개로 만든 후 backward** — 다출력은 설계에서 배제하고 사용자가 해결
- 노트 34 §5 연결: 다출력은 야코비안/VJP의 이론적 영역 — DeZero는 그 영역을 명시적으로 포기한 것

### ★★ 그래프는 항상 자란다 — 값은 소멸해도 계산 이력은 성장 (2026-08-31, 이슈 45 도구로 발견)

> **책이 다루지 않는 발견** — 이슈 45의 다층 그래프 시각화 도구(`plot_multi_layer_graph`)로 x²의 1~4계 미분을 실험하다 발견. 브로: *"이게 x²인데 그래프가 점점 커져? 이상하지 않나?"*

**실험 결과** (x = 2.0, y = x²):

| 계 | 값 (미분 결과) | Function 수 | 성장 |
|---|---|---|---|
| 순전파 | y = 4.0 | 1 | — |
| 1계 | y' = 4.0 (= 2x) | 3 | +2 |
| 2계 | y'' = 2.0 | 5 | +2 |
| 3계 | y''' = 0.0 | 7 | +2 |
| 4계 | y'''' = -0.0 (부호 있는 0) | 9 | +2 |

- **값은 소멸해도** (x² → 2x → 2 → 0 → 0) **그래프는 선형 성장** (+2/회)
- 이건 tanh처럼 미분식에 자기 자신이 등장하는 경우가 아니어도 마찬가지 — **chain rule이 매번 새 중간값을 만들기 때문**
- 성장률은 함수에 따라 다름: x² = 선형 (+2), exp = 거의 0, tanh = 지수 (2배씩)

**값과 그래프의 완전한 분리**:

- **미분식 (symbolic)**: x² → 2x → 2 → 0 — 답이 점점 간단해짐 ("소멸" 패턴, 노트 32)
- **계산그래프 (autodiff)**: 1 → 3 → 5 → 7 → 9 — 계산 이력이 계속 쌓임
- 비유: 간단한 요리 결과(0)도 요리 과정의 조리도구와 중간 재료는 많을 수 있음

**autodiff의 정직한 중간값** — symbolic 미분이면 즉시 사라질 값들이 그래프에 기록됨:

| 계 | 새로 등장하는 Pow | 이유 |
|---|---|---|
| 2계 | Pow(x, 0) → x⁰ = 1 | d(x¹)/dx = 1·x⁰ |
| 3계 | Pow(x, -1) → x⁻¹ = 0.5 | d(x⁰)/dx = 0·x⁻¹ — **0에 곱해질 운명이어도 계산됨** |
| 4계 | Pow(x, -2) → x⁻² = 0.25 | d(x⁻¹)/dx = -1·x⁻² |

- 패턴: **n계 미분의 그래프에는 x^(2-n)이 등장** — chain rule의 c·x^(c-1)이 지수를 하나씩 내리면서 중간값을 계속 생산
- symbolic 미분이라면 `0 × x⁻¹ = 0`으로 간단히 되어 x⁻¹은 등장하지 않지만, autodiff는 **계산한 것은 정직하게 기록**

**노트 32 "그래프 3형태"와의 관계**:

- 노트 32의 소멸·순환·폭증은 **미분식의 복잡도 패턴** 분류
- 본 발견은 **계산그래프의 크기**는 별개의 축 — 미분식이 "소멸"(x²의 경우)해도 그래프는 "성장"
- 두 축의 조합이 실제 비용을 결정:

| 미분식 패턴 | 그래프 성장 | 총 비용 |
|---|---|---|
| 소멸 (x²) | 선형 | 저렴 (그래도 자람) |
| 유지 (exp) | 거의 0 | 매우 저렴 (재사용형) |
| 폭증 (tanh) | 지수 | 매우 비쌈 |

**왜 1계 미분이 압도적으로 쓰이는가의 진짜 이유** — 수학이 어려워서가 아니라 **계산그래프가 계속 자라서**. 2계는 그래프가 2배, 3계는 3배... 비용이 선형 이상으로 증가하며, tanh류는 지수 폭발. 신경망 파라미터 수백만 개에서는 그래프 성장이 치명적.

**★ 추가 발견 — 새 계산의 양은 미분식 복잡도를 따른다** (2026-08-31 저녁, 브로 실험 관찰):

총 그래프 크기는 자라지만, 각 계층의 **새로 계산된 노드 수**는 다른 패턴을 보임:

| 계층 | 총 노드 | 새 노드 | 복제(재사용) | 재사용 비중 |
|---|---|---|---|---|
| 순전파 | 3 | 3 | 0 | 0% |
| 1계 | 8 | 7 | 1 | 12% |
| 2계 | 12 | 9 | 3 | 25% |
| 3계 | 14 | **7** | 7 | **50%** ← 역전! |
| 4계 | 16 | **5** | 11 | **69%** |

- 새 계산량: 3 → 7 → 9 → **7** → **5** — 2계가 정점, 3계부터 **감소**
- 미분값이 0으로 소멸할수록 새로 계산할 것이 줄고, 기존 값 재사용 비중이 커짐
- ★ 정밀화: "그래프는 자란다" = **총량은 누적되지만, 새 계산의 양은 미분식 복잡도를 따름** — x²는 소멸형이므로 새 계산도 감소. tanh(폭증형)이라면 새 계산이 지수 증가할 것 (검증 예정)

**내일 조사 리스트** (2026-08-31 브로 작성):

1. x² 상위 계산그래프에서 사용자 코드 입력변수가 아닌 스칼라 값 Variable 노드가 함수에 참조되지 않고 홀로 그려지는 것 — 버그인가? (고아 노드)

3. cluster 경계선 색상을 미분 차수에 따라 다르게 (너무 튀지 않게)
4. 항등함수(identity) 추가 → 2*x, 다양한 함수로 테스트 — 노트 32의 미분식 분류(출력형/입력형/입출력형/상수형) 각 최소 1개씩 점검

**관측 도구**: `plot_multi_layer_graph([y, gx, gx2, ...])` — 이슈 45 구현. 여러 층의 그래프를 한 장에 병합 + cluster 그룹핑 + 공유 변수 복제(점선 참조). 기존의 "각각 따로 그린 PNG에서 노드 번호 수동 대조" (step35 방식)를 대체.

## 10. 네이밍 성찰 — fill_grad라는 이름, 28스텝 만에 다시 보다

> 브로: *"중간 노드에도 저장하면서 이동하는 구현이니 fill(채우다)이 의미가 있었을 듯하면서도, 이제 와서 보니 적절했는지?"*

**fill이 맞는 이유** — 부수 효과를 정확히 기술: 리턴값 **None**, 각 Variable의 grad 필드를 변경하는 side effect가 본체. "fill"이 이를 정확히 암시 (채우고 끝, 리턴 없음). dezero의 `backward()`는 "계산하다" 뉘앙스, `fill_grad`는 "저장하다" 뉘앙스.

**브로가 어색하다고 느낀 이유**: ① 누적도 하는데 fill인가 (첫 채우고 이후 더함) / ② 본질은 chain rule 아닌가 (fill은 결과지 과정이 아님) / ③ 중간 노드는 버리는데 (retain_grad=False면 채웠다가 버림).

**대안 함수명 — chain rule 연쇄 관점 부각**:

| 대안 | 강조점 | 근거 |
|---|---|---|
| `chain_grad` | chain rule 연쇄 | 국소 미분 × upstream을 연쇄 — 과정을 직접 지칭 |
| `propagate_grad` | 전파 | gradient가 그래프를 타고 퍼져나감 — PyTorch docs도 "gradient propagation" 사용 |
| `backprop` | 역방향 계산 | 업계 표준 — dezero의 backward와 같은 강조점, 전역 함수 버전 |
| `fold_grad` | fold(접기) | right fold = 역전파의 본질 (step07 탐구) — FP 관점 |
| `reduce_grad` | 수집 | 각 리프에 gradient를 수집·누적 — FP reduce |

★ 판정: `fill_grad`가 나쁘지 않은 이유는 "리턴 없이 상태 변경"이라는 특이성을 이름에 담았기 때문. 대안들이 chain rule 본질을 더 잘 담지만, "fill"이 아니면 None 반환의 이유가 이름에서 사라짐. 네이밍 트레이드오프: **과정(chain rule) vs 결과(저장)** — 둘 중 하나만 이름에 담을 수 있고, step08에서 선택한 건 결과 쪽 (항목 015).
