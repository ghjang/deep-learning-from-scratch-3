## 1. 함수 해부 — 두 항이 각자 역할을 한다

```
y = 100(x1 - x0²)²  +  (x0 - 1)²
    ────── A 항 ─────   ── B 항 ──
```

| 항 | 역할 | 지형적 의미 |
|---|---|---|
| **A**: `100(x1 - x0²)²` | x1이 `x0²`에서 벗어날수록 벌칙 | **골짜기 바닥을 포물선 x1 = x0²를 따라 형성** |
| **B**: `(x0 - 1)²` | x0 = 1 방향으로 낮아지는 경사 | 골짜기를 따라 내려가는 **축 방향 기울기** |

- 둘 다 제곱 → y ≥ 0. 최소 0은 두 항 동시 0: `x0 = 1` (B) ∧ `x1 = x0² = 1` (A) → **최소점 (1, 1)**.
- ★ 핵심: **골짜기 바닥이 직선이 아니라 곡선(포물선)**. 등고선이 바나나 모양인 이유.

## 2. 증거 — step28 데모 궤적에 나타난 "낙하 → 크롤링"

골짜기 바닥 편차 `x1 - x0²`를 궤적에 함께 출력했다 (step28 [1]):

```
iter   0: x0 = 0.0024, x1 = 1.6000 | 편차 +1.6000   ← 골짜기 위에서 시작
iter 100: x0 = 0.2358, x1 = 0.0527 | 편차 -0.0029   ← 바닥에 착지!
iter 500: x0 = 0.5292, x1 = 0.2777 | 편차 -0.0024   ← 바닥 붙어 기어감
iter 999: x0 = 0.6837, x1 = 0.4660 | 편차 -0.0015   ← 여전히 바닥, 천천히 전진
```

경사하강법의 2단계 동작이 숫자로 보인다:
1. **낙하 단계** (초반): 편차 +1.6 → -0.003. 골짜기 바닥으로 수직 급강하.
2. **크롤링 단계** (이후): 편차 ≈ -0.002 유지하며 바닥을 따라 x0=1 방향으로 기어감.

## 3. 왜 느린가 — gradient가 "가야 할 방향"을 안 가리킨다

경사하강법은 매 순간 `-gradient` 방향으로 간다. 그런데 이 지형에서:

- **골짜기 횡단 방향** (A항 지배, 계수 100) → gradient **매우 큼**
- **골짜기 축 방향** (B항) → gradient **작음**

즉 gradient 벡터는 거의 횡단 방향만 가리킨다. 최소점 (1,1)은 골짜기를
**따라** 가야 있는데, 알고리즘은 바닥으로 눌린 뒤 미세하게만 축 방향으로
전진한다. 길고 좁고 **굽은** 그릇 — 전문용어로 **조건수가 나쁘다(ill-conditioned)**.

Hessian 관점: 횡단 방향 곡률 ≫ 축 방향 곡률. 좁고 길쭉한 타원 등고선에서
경사하강법은 지그재그 진동하며 느리게 수렴하는 것이 수학적으로 알려져 있다.

## 4. lr 딜레마 — 하나의 학습률로 두 방향을 못 만족시킨다

step28 [2] 실험: lr=0.001 정상 / **lr=0.01부터 발산**.

- lr을 크게 → 횡단 방향 곡률(100 계수) 때문에 바닥을 통째로 건너뛰어
  반대편 벽에 박고 오버슈트 증폭 → 발산.
- lr을 작게 → 발산은 안 하지만 축 방향 스텝도 같이 작아져 영영 기어감.

**방향별로 필요한 스텝 크기가 다른데 lr은 하나** — 이게 ill-conditioning의
실용적 고통이고, 좌표별 스케일링/모멘텀/뉴턴 방법 같은 개선 알고리즘의 동기.

## 5. 역사 — Rosenbrock의 의도 (1960)

- Howard H. Rosenbrock이 1960년 논문에서 자신의 회전 좌표계 최적화 알고리즘
  시험용으로 제안한 함수.
- 1960년대는 수치 최적화 알고리즘 폭발기 — "내 방법이 남들보다 낫다"를
  보이려면 **남들의 방법이 실패하는 어려운 문제**가 필요했다.
- Rosenbrock 함수는 "단순 경사하강법이 요령 없이 헤매는 지형"의 표준 시험대가
  되어 지금까지 회자 — 딥러닝 프레임워크 튜토리얼의 단골.

## 6. 시험 함수 디자인의 사고법 — "원하는 어려움을 수학 성질로 번역한다"

브로 잡생각("이런 함수를 어떻게 생각하지?")에 대한 답.

디자이너들은 창작이 아니라 **역설계**를 한다. "어떤 알고리즘이 어떻게 실패하는가"를
먼저 정하고, 그 실패를 강제하는 지형을 수학적으로 조립한다:

| 원하는 어려움 | 번역된 수학적 장치 | 대표 함수 |
|---|---|---|
| 기본기 시험 (통제군) | 완전한 대칭 그릇 | **Sphere** `x²+y²` |
| 골짜기를 따라 느린 수렴 | 바닥을 곡선으로 + 횡단 곡률 크게 | **Rosenbrock** |
| 지역 최소에 빠짐 | 주기적 웨이브로 국소 최소량산 | **Rastrigin** (사인 항) |
| 평탄 지대에서 탐색 방황 | 바깥 지수 평탄부 | **Ackley** |
| 최소점이 여러 개 | 4개의 등가 최소점 | **Himmelblau** |
| 최소점이 가장자리에 붙음 | 부등식 제약 변환 | 여러 constrained 벤치마크 |

공통 패턴: **"simple formula, hard geometry"** — 몇 글자 안 되는 식에서
복잡한 지형이 창발하도록 설계. 각 항이 지형의 한 재료(바닥 모양/경사/장애물)를
담당한다. Rosenbrock에서 A항=골짜기 바닥, B항=축 경사였던 것처럼.

이 관점에서 벤치마크 함수를 읽으면 "이상한 수식 모음"이 아니라
**"알고리즘의 특정 약점을 겨냥한 함정 설계도"**로 읽힌다.

## 7. NFL 정리 — "상위호환"은 존재하지 않는다

"그럼 최적화 알고리즘에 상위호환이란 건 없을까?"라는 자연스러운 다음 질문에
수학이 답한다. Wolpert & Macready (1997)의 **No Free Lunch 정리**:

> 모든 가능한 문제들에 대해 평균을 내면, 어떤 최적화 알고리즘도
> 다른 알고리즘보다 낫지 않다.

직관: A가 어떤 문제군에서 B보다 잘하는 만큼, 다른 문제군에서 정확히
그만큼 뒤진다. 알고리즘 성능이 상쇄 제로섬으로 짝지어 있다. 하나를
크게 만들려면 문제 공간에 대한 **가정(구조)** 을 넣어야 하는데, 그 가정이
안 맞는 문제에서는 망한다 — Rosenbrock이 "경사만 믿는 방법"의 가정을
깨는 지형이었던 것처럼.

★ 6절(역설계)과의 맞물림: **약점이 있으니 겨냥이 가능하고, 겨냥이
가능하다는 건 만능이 없다는 뜻이다.** 벤치마크의 존재 자체가 NFL의 증거.

### 현실의 선택 척도 — 트레이드오프 축

NFL이 "평균" 이야기라면 실전은 "우리 문제의 구조" 이야기:

| 척도 | 질문 |
|---|---|
| 1회 반복 비용 | gradient만? (O(n)) Hessian도? (O(n²)~O(n³)) |
| 수렴 속도 | 1차: 선형 수렴 / 2차(뉴턴): 제곱 수렴 |
| 메모리 | 파라미터 n개에 몇 배 저장? |
| 안정성 | lr/초기값 민감도 |
| 비볼록 대응 | 지역 최소/안장점 탈출 능력 |

### 최고의 예 — "뉴턴이 이론상 압살인데 왜 딥러닝은 SGD 쓰나"

- 뉴턴: 2차 정보(Hessian)로 **제곱적 수렴** — 이론상 우위.
- 현실: 파라미터 수백만~수십억 개면 Hessian(n×n)은 **메모리에도, 계산에도 불가능**.
- gradient는 **역전파로 O(n)** 에 계산 가능 — 우리가 27 step 동안 만든 게 바로 이것.
- 역설: SGD의 노이즈가 비볼록 지형에서 오히려 나쁜 지역 최소를 튕겨내는 데 유리.

→ **"이론적 우위 ≠ 실제 선택"**. 문제 구조(차원/볼록성/비용 구조)가 알고리즘을 결정.
그래서 "선택 지도" — 문제 구조의 좌표에서 누가 빛나는지 찍어가는 학습 — 가
곧은 길이다. step28 경사하강법 → step29 뉴턴 → 이후 SGD 계열로 지도가 확장된다.

## 8. 책의 스토리 라인에서의 위치

이 선택 지도 위에서 3고지의 서사가 전개된다:
**경사하강법의 한계 체감 → 뉴턴 방법의 등장**.

- step28: Rosenbrock에서 경사하강법이 기어가는 걸 체감
- step29: 뉴턴 방법 `x.data -= grad / f''(x)` — 2차 미분(곡률) 정보로
  골짜기의 곡률을 보정해 훨씬 적은 스텝에 수렴
- 즉 Rosenbrock은 단순 벤치마크가 아니라 **다음 step의 동기를 세우는 장치**

## 10. 🎯 결론

- Rosenbrock = **바닥이 포물선인 좁고 굽은 골짜기**를 만드는 설계.
  A항이 골짜기 바닥(x1 = x0²), B항이 축 방향 경사.
- 느린 이유 = gradient가 횡단 방향 위주 → 바닥에 붙은 뒤 축으로만 기어감
  (데모 궤적 편차로 실증).
- 시험 함수 디자인 = **알고리즘의 실패 모드를 지형으로 역설계**하는 기술.
  Rosenbrock은 "경사만 믿는 방법"을 함정에 빠뜨리기 위한 1960년의 걸작.
- 만능 알고리즘은 없다 (NFL 정리) — 질문은 "누가 낫냐"가 아니라
  **"우리 문제의 구조에서 누가 빛나냐"**.
