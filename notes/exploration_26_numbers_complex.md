## 1. `__truediv__` vs `__floordiv__` vs `__mod__` — 파이썬 나눗셈의 3총사

step22에서 `__truediv__`를 쓰면서 "왜 true인가?"부터 시작.

### 세 가지 나눗셈

```python
7 / 2      # → 3.5     (진짜 수학 나눗셈, 소수점 유지)  → __truediv__
7 // 2     # → 3       (몫만, 소수점 버림)             → __floordiv__
7 % 2      # → 1       (나머지만)                      → __mod__
```

### 왜 "true"라고 부르나 — 파이썬 2 vs 3 역사

**파이썬 2 시절 혼란**:
```python
# 파이썬 2
7 / 2      # → 3    ← 정수/정수 = 정수 (소수점 버림) ★
7.0 / 2    # → 3.5  ← 하나라도 소수면 소수 결과
```

파이썬 2의 `/`는 피연산자 타입에 따라 동작이 달라져 혼란. 파이썬 3에서 개선:
- `/` → **"진짜(true) 수학 나눗셈"** (항상 소수 반환)
- `//` → "몫만" (새로 만듦)

`__truediv__`의 "true"는 **파이썬 3가 파이썬 2의 혼란을 바로잡았다는 역사적 자부심**. "이번엔 진짜 제대로 된 나눗셈이다!" (PEP 238).

### DeZero/PyTorch는 `__truediv__`만 쓰는 이유

`//` (floordiv)는 미분 가능하긴 한데(계단 함수라 불연속), **신경망/수학에서 안 씀**. 딥러닝은 연속 수학이라 `//` 같은 정수 나눗셈이 의미 없음. 따라서 `__truediv__`만 정의하는 게 자연스러운 선택.

## 2. 파이썬 숫자 계층 — int / float / complex

"점이 들어간 수는 무슨 타입?" (브로 질문) → 파이썬 숫자 체계로.

### 리터럴 규칙

```python
3          # → int     (정수)
3.0        # → float   (실수 — 점 있으면 float!)
3.14       # → float
.5         # → float   (정수부 생략 가능, 0.5)
2e3        # → float   (지수 표기, 2000.0)
1_000.5    # → float   (밑줄은 가독용, 무시됨 — 1000.5)
2 + 3j     # → complex (★ 'j' 접미사로 복소수 리터럴)
```

### 자료형 계층

| 타입 | 비트 수 | 정밀도 | 용도 | 특징 |
|---|---|---|---|---|
| `int` | 가변 | **임의 정밀도** | 정수 | ★ 오버플로 없음! C/Java와 다른 점 |
| `float` | 64비트 | 배정도 (double) | 실수 | C의 `double`과 동일 (IEEE 754) |
| `complex` | 128비트 | 배정도×2 | 복소수 | ★ 파이썬이 기본 지원 (드문 case) |

### ★ 브로 정정 — 파이썬 float은 64비트 배정도야

브로 추측: "NumPy에 float64 있으니 파이썬 float은 32비트?"
→ **반대**. 파이썬 `float`은 64비트 배정도(고정). NumPy가 **추가로** float32 옵션을 제공하는 것.

| 타입 | 비트 | 어디서 |
|---|---|---|
| 파이썬 `float` | **64비트 배정도** | 파이썬 기본 (고정, C의 double) |
| `np.float64` | 64비트 | NumPy (파이썬 float과 동일) |
| `np.float32` | **32비트 단정도** | NumPy (★ 추가 옵션 — 딥러닝 메모리 절약용) |

★ 왜 float32가 딥러닝에 필요한가 — GPU 메모리 절약. float64 대비 절반 메모리로 큰 모델 훈련 가능. 단, 정밀도 떨어짐 (`0.1 + 0.2` 오차가 더 큼).

### int 임의 정밀도의 증거

```python
2 ** 100
# → 1267650600228229401496703205376  (31자리)
# ★ C/Java에선 64비트 넘으면 오버플로, 파이썬은 자동으로 큰 수 표현
```

### float 정밀도 한계의 증거

```python
0.1 + 0.2
# → 0.30000000000000004    ← ★ 0.3이 아님! 부동소수 오차
```

이게 바로 딥러닝에서 "완전히 정확한 값"이 안 나오는 이유. autodiff의 미세한 오차도 여기서 비롯.

참고: [0.30000000000000004.com](https://0.30000000000000004.com/) — 모든 프로그래밍 언어에서 이 현상 정리.

## 3. 복소수 — 파이썬이 기본 지원하는 이유

### cmath 모듈 (기본 내장)

```python
import cmath  # ★ 파이썬 표준 라이브러리 (C의 <complex.h> 래핑)

z = 3 + 4j
abs(z)                  # → 5.0    (크기)
z.conjugate()           # → 3-4j   (켤레)
cmath.exp(1j * math.pi) # → -1     (★ 오일러 공식 자동 적용)
cmath.sqrt(-1)          # → 1j     (★ 음수 제곱근도 OK, math.sqrt는 에러)
```

### 파이썬이 복소수를 기본 지원하는 진짜 이유

**수학/과학 계산 생태계**. 파이썬이 "科学 계산용 언어"로 설계된 흔적:
- 푸리에 변환 (신호 처리)
- 양자역학 (파동함수 = 복소함수)
- 전기공학 (교류 회로 = 복소 임피던스)
- 제어 공학 (라플라스 변환)

이런 분야에선 복소수가 **기본 도구**. 파이썬이 언어 차원에서 지원하는 건 이 생태계를 위한 설계. NumPy도 `np.fft`(푸리에), 복소 ndarray를 지원.

★ cf. Java/C#은 복소수 기본 타입 없음 (라이브러리로만). 이런 점에서 파이썬이 과학 계산에 더 친절.

### ★ 브로 통찰 — "복소수는 2입력 2출력 폼?"

브로: "실수/복소수를 '원수'라 안 부르지만... 복소수는 일종의 '벡터 함수'라는 '2개 입력, 2개 출력'의 폼?"

**정확함. ★★★** 복소수 `z = a + bi`는 본질적으로 **2차원 벡터** `(a, b)`. 그래서 복소 함수 `f(z)`는 이렇게 해석 가능:

```
f(z) = f(a + bi) = u(a, b) + i·v(a, b)
       ↑                ↑          ↑
       복소 입력        실수부    허수부
       (2개 값)         (2개 출력값)
```

즉 복소 함수 `f: ℂ → ℂ`는 **`ℝ² → ℝ²` 함수와 본질 동일**. 이 관점이 **코시-리만 방정식**으로 이어짐 (§5).

### "왜 'n원수'라고 안 부르나"

수학에 **4원수(quaternion)**, **8원수(octonion)** 같은 게 있긴 함:
- 1원수 (real) — ℝ, 교환법칙 O, 결합법칙 O
- 2원수 (complex) — ℂ, 교환법칙 O, 결합법칙 O
- 4원수 (quaternion) — ℍ, 교환법칙 **X**, 결합법칙 O
- 8원수 (octonion) — 𝕆, 교환법칙 X, 결합법칙 **X**
- 16원수 이상 — 구조 안 됨 (절단 정리)

★ 2배마다 대수 구조가 하나씩 깨짐 (교환 → 결합 → ...). 이런 수학적 계보가 있는데, 일반적으로 "실수/복소수"라 부르고 4원수 이상은 특수 분야(3D 그래픽, 양자정보)에서만 씀. 파이썬도 복소수까지만 기본 지원.

## 4. ★★★ 오일러 공식 — 가장 아름다운 수식

```
e^(iπ) + 1 = 0
```

### 파이썬으로 검증

```python
import cmath, math
cmath.exp(1j * math.pi)
# → (-1+1.2246467991473532e-16j)   ← 사실상 -1 (부동소수 오차)

cmath.exp(1j * math.pi) + 1
# → 1.22e-16j                       ← 사실상 0 ★ 오일러 공식 검증!
```

### 일반형 — e^(iθ) = cos(θ) + i·sin(θ)

```python
theta = math.pi / 4   # 45도
cmath.exp(1j * theta)
# → (0.7071... + 0.7071...j)
# ★ real = cos(θ), imag = sin(θ) — 오일러 공식 자동 분해
```

### 왜 "가장 아름다운 수식"인가

5개의 **근본 상수**가 하나의 식에 등장:
- `e` — 자연대수 (미적분의 핵심)
- `i` — 허수단위 (대수학의 핵심)
- `π` — 원주율 (기하학의 핵심)
- `1` — 곱셈 항등원 (산술의 핵심)
- `0` — 덧셈 항등원 (산술의 핵심)

게다가 **3개의 기본 연산**(덧셈, 곱셈, 거듭제곱)이 한 식에 등장. 수학의 여러 분야가 하나로 수렴하는 순간. 수학자들 사이에서 "신의 서명"이라 불림.

### ★ 오일러 공식의 진짜 중요성 — "주기성과 지수의 결합"

브로 통찰:
> "오일러 공식의 우변은 '사인과 코사인', 즉 '주기성, 반복성'을 표현하는 수학의 도구가 보인다"

**정확함. ★** 오일러 공식의 핵심은 **"회전(주기성)을 지수로 표현"** 한다는 것. 왜 중요한가 — sin/cos가 곱셈/미분에 약한 반면, **지수는 곱셈/미분에 강함**. 그래서:

```
푸리에 변환: sin/cos를 복소 지수로 바꿔 계산 간단히
양자역학: 파동(주기성)을 복소 지수로 표현
제어공학: 라플라스 변환 (미분방정식 → 대수방정식)
```

→ 모든 곳에서 "주기적 현상을 지수로 변환"해서 풀이 단순화. 오일러 공식이 현대 과학의 기반.

### 복소수 거듭제곱 — 드무아브르 정리

```python
z = 1 + 1j
z ** 2  # → 2j
z ** 3  # → (-2+2j)
z ** 10 # → 32j   ← 파이썬이 복소수 거듭제곱 자동 계산
```

`z = r·e^(iθ)` 꼴이면 `z^n = r^n·e^(inθ)` — 크기는 n제곱, 각도는 n배 회전. 기하학적 해석 깔끔.

## 5. ★★★ 복소수 미분 — 왜 어려운가

### 핵심 어려움 — 복소 미분은 "2차원 미분"

실수 미분은 1차원 선 위에서의 변화율:
```
df/dx = lim(h→0) [f(x+h) - f(x)] / h
```

복소 미분은 **2차원 평면 위에서의 변화율**:
```
df/dz = lim(h→0) [f(z+h) - f(z)] / h   (★ h도 복소수!)
```

문제: h가 복소수니까 x축 방향(+h)으로 가느냐, y축 방향(+ih)으로 가느냐에 따라 극한값이 **다를 수 있음**. 즉 **방향 의존적**.

### 코시-리만 방정식 — "잘 동작하는" 조건

"어느 방향으로 가도 미분값이 같은 함수" = **정칙 함수**(holomorphic).

조건: `f(z) = u(x,y) + i·v(x,y)` 일 때,
```
∂u/∂x = ∂v/∂y
∂u/∂y = -∂v/∂x
```

이 조건을 만족하는 함수만 "진짜 미분"이 정의됨.

- 정칙 함수 예: `z²`, `e^z`, `sin(z)`, 다항식
- 비정칙 예: `z̄` (켤레), `Re(z)`, `Im(z)`, `|z|`

### 위팅거 도함수 — autodiff에서 실제로 쓰는 도구

복소 함수를 미분할 때 z로 직접 미분하면 안 되고:
```
∂f/∂z   = (1/2)(∂f/∂x - i·∂f/∂y)     ← 위팅거 도함수
∂f/∂z̄  = (1/2)(∂f/∂x + i·∂f/∂y)     ← 켤레에 대한 도함수
```

PyTorch/JAX가 복소 미분 구현에 사용하는 도구. 이상해 보이지만 이래야 chain rule이 깔끔.

### PyTorch/JAX의 복소 미분 지원 (2020년대)

| 프레임워크 | 복소수 지원 시기 | 비고 |
|---|---|---|
| PyTorch | 2020년 (v1.6~) | 실험적 시작 |
| JAX | 2019년부터 | 비교적 빠름 |
| TensorFlow | 2020년대 | 지원하지만 제약 |

→ 왜 이렇게 늦었나 — 복소 미분의 복잡성(위팅거, 코시-리만) 때문. 실수 autodiff보다 훨씬 어려움.

### DeZero는 실수만

책 3권의 DeZero는 실수만 다룸. 복소수는 "미래 확장 아이디어" 정도. step25~32(경사하강법/뉴턴 방법)에서도 실수 미분만 씀.

## 6. ★★★★ 무한 번 미분 가능성 ↔ 기울기 소실 (브로 통찰 하이라이트)

브로:
> "이 시점에서 '무한번 미분 가능성'과 '기울기 소실'이 떠오르는 건 좀 재미있네"

**이 연결이 이 노트의 진짜 하이라이트. ★★★★**

### 복소 해석학의 경이 — "정칙이면 무한 번 미분 가능"

복소 함수가 한 번 정칙이면 **자동으로 무한 번 미분 가능**해짐. 실수에선 상상도 못 할 일:
- 실수 예: `f(x) = |x|` — 한 번도 미분 불가 (원점)
- 실수 예: `f(x) = x·|x|` — 한 번은 미분, 두 번째는 불가 (원점)
- 실수 예: 더 매끄럽게 만들 수 있지만, "n번 미분 가능"과 "n+1번 미분 가능"은 다른 조건

반면 **정칙 함수는 한 번 조건 만족하면 무한 번 미분 가능** (코시 적분 공식에서 도출). 이게 복소 해석학이 "실수 해석학보다 우아하다"고 불리는 이유.

### ★★★ 그런데 "무한 번 미분 가능" ↔ "기울기 소실"이 왜 연결되나

브로 직관의 핵심. 정확히 짚어보자:

#### 연결 1: sin/cos/e^x 는 무한 번 미분해도 "모양" 안 바뀜

```python
# sin 함수
sin(x)      → 미분 → cos(x)
cos(x)      → 미분 → -sin(x)
-sin(x)     → 미분 → -cos(x)
-cos(x)     → 미분 → sin(x)     ← ★ 4번 미분하면 원래로!
```

sin/cos/e^x는 **미분해도 "크기"가 커지지도 작아지지도 않음** (순환하거나 자기 자신으로).

#### 연결 2: sigmoid 함수 = 오일러 공식의 변형 ★★★

딥러닝 활성화 함수 sigmoid:
```
σ(x) = 1 / (1 + e^(-x))
```

이건 **오일러 공식의 실수 버전**의 변형이야. ★ sigmoid 도함수:
```
σ'(x) = σ(x)·(1 - σ(x))    ← ★ 자기 자신을 참조하는 재귀적 구조
```

이 도함수의 **최댓값**이 `0.25` (x=0일 때). ★ 이 숫자가 기울기 소실의 원인.

#### 연결 3: 체인 룰 곱셈 — "기울기 소실"의 산술적 원인

신경망 역전파는 chain rule의 연속 곱셈:
```
최종 기울기 = ∂L/∂a₁ × ∂a₁/∂a₂ × ∂a₂/∂a₃ × ... × ∂aₙ₋₁/∂aₙ
```

각 항이 `0 < x < 1`이면, **곱할수록 0으로 수렴**:
```
0.25 × 0.25 × 0.25 × ... (n층)
→ 0.25^n → 0   (★ 지수적 감소)
```

10층이면 `0.25^10 ≈ 1e-6`. 입력층 기울기는 거의 0. → 학습 안 됨.

#### ★★★ 브로 통찰의 정확한 연결 — 왜 "무한 미분 가능"이 "기울기 소실"이 되나

핵심: **"무한 번 미분 가능"하다는 건, 함수가 극도로 부드럽다는 뜻**.

부드러움 = 변화가 완만 = 도함수의 크기가 작다 (급격한 변화가 없음).
- e^x는 무한 번 미분 가능 → 도함수도 e^x (일정한 크기)
- sin/cos는 무한 번 미분 가능 → 도함수 크기 ≤ 1 (순환)
- sigmoid는 무한 번 미분 가능 → ★ 도함수 크기 ≤ 0.25 (작음!)

즉 "부드럽다"는 게 **양날의 검**:
- 장점: 수학적으로 다루기 쉽다 (어디서든 미분 가능)
- 단점: **도함수가 작아서, 층이 깊어지면 기울기가 소실** ★★★

"무한 번 미분 가능한 매끄러운 함수"가 딥러닝에 쓰이면, 그 매끄러움이 역전파 시 **기울기를 0으로 죽이는** 역설. 브로가 직관한 연결의 본질.

#### 연결 4: ReLU의 등장 — "미분 불가"한데 왜 더 잘 되나

ReLU: `f(x) = max(0, x)`
- ★ 원점에서 **미분 불가** (껍질이 있음)
- 양수 영역: 도함수 = 1 (★ sigmoid의 0.25보다 4배 큼!)
- 음수 영역: 도함수 = 0

→ "무한 번 미분 가능하지 않음에도 불구하고" ReLU가 sigmoid보다 깊은 신경망에서 잘 작동.
이유: **도함수 크기가 1**이라 기울기 소실이 덜함.

★ 아이러니: 수학적으로 **덜 부드러운(미분 불가) 함수**가 딥러닝에선 **더 잘 작동**. 왜냐면 부드러움이 기울기를 죽이니까. 브로 통찰이 가리킨 역설.

### 이 연결이 왜 중요한가

1. **수학적 아름다움 ↔ 공학적 한계의 충돌** — 복소 해석학의 "무한 미분 가능"이 딥러닝에선 "기울기 소실"로 돌아옴.
2. **ReLU가 "못생긴" 함수인데 더 잘 되는 이유** — 미분 불가능한 점(원점)이 있어도 도함수 크기가 커서 학습 잘 됨.
3. **활성화 함수 선택이 수학적 철학과 연결** — sigmoid(매끄러움) vs ReLU(껍질) 선택이 단순한 empirical choice가 아니라 **미분 가능성/기울기 크기**와 연결된 깊은 문제.

→ step40+ (신경망 구축)에서 활성화 함수 다룰 때 이 통찰이 다시 떠오를 것. 영구 기록 가치.
