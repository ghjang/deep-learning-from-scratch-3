# 탐구 33 — 이미 계산된 세계에서의 미분: Define-by-Run의 평가 시점

> **시점**: step36 진행 중 (2026-08-24)
> **상태**: ✅ 완료 (step36 z = gx³+y 예시의 혼란을 정리하며 도출)
> **트리거**: 브로 대혼란 — *"2차 미분 시에도 최초 입력값이 유지된 채 계산된다는 상황이니?
> 변수의 grad엔 n차 미분값이 들어있고 그래프 리턴값엔 식의 평가값이 들어있고?
> 내가 지금 뭘 헷갈리는 거야?"* — 답: **아무것도 헷갈린 게 없었다. 정확히 보고 있었다.**

## 📌 브로 서술 검증 — 4항목 전부 정확

> *"오버로딩으로 구성한 식은 계산 그래프를 구성하고 그 시점에 이미 함수의 평가(순전파)가
> 일어나서 최종 변수에 저장되어 있고, 입력 변수도 값이 들어가있고, 이때 fill_grad를
> 때리면 이미 고정된 입출력 값이 있는 상태에서 백프로퍼게이션으로 미분을 수행하고,
> 최종적으로 입력 변수의 grad에 최초 입력에 대한 전체 합성식의 미분값을 저장한다는 소리지?"*

| # | 서술 | 검증 | 보강 |
|---|---|---|---|
| 1 | 식 구성 = 그래프 구성 + 동시 평가 | ✅ | Define-by-Run의 정의 자체 — "실행이 곧 정의" |
| 2 | 입력 변수도 값이 들어가있음 | ✅ | x.data=2, **끝까지 불변** |
| 3 | 고정된 입출력 값 상태에서 미분 | ✅ | **중간값들도 다 고정** (y=4, gx=4). backward는 저장된 값을 재계산 없이 재사용해 도함수 평가 |
| 4 | 입력 변수 grad에 전체 합성 미분값 | ✅ | 모든 **리프**에 각자 grad (다변수면 각 입력마다), retain_grad=True면 중간에도 |

## 1. 핵심 원칙 — 모든 것은 "x=2라는 한 점에서의 평가"

Define-by-Run에서 미분 결과는 f'(x)라는 **함수**가 아니라 **f'(2)라는 숫자**다.
그래프 자체가 "x=2에서 평가된 식"이므로, 역전파도 그 점에서의 값으로 즉시 계산된다.

- 1차 미분 → y'(2) = 4 (숫자)
- 2차 미분 → y''(2) (숫자)
- step36의 z' → z'(2) = 100 (숫자)

"n차 미분을 했다" = n차 도함수를 손에 넣었다(X), **그 한 점에서의 n차 미분값을 얻었다**(O).

## 2. Variable의 이중성 — 값과 식의 동거

| Variable가 가진 것 | 내용 | step36에서 |
|---|---|---|
| `.data` | **식의 평가값** (x=2에서 계산한 숫자) | y.data=4, gx.data=4, z.data=68 |
| `.grad` | **마지막 역전파가 이 변수에 모은 미분값** | 시점마다 갱신 (아래 표) |
| `.creator` | **식의 구조** (그래프가 살아있다는 증거) | gx.creator → "2x"의 구조 |

grad의 생애: "현재까지의 n차 미분값이 **쌓이는** 게 아니라", **최근 fill_grad 대상의
미분값으로 그때그때 채워진다** (clear_grad로 초기화 후 재충전).

### ★ data는 "규약적 불변", grad는 "기록 슬롯" (브로 관찰에서 도출)

브로: *"일종의 immutable 패턴이 입력/출력 값엔 적용되는데 grad는 변한다?"* —
절반 정확 + 미묘한 반전:

- **grad (변함 — 본질)**: 최근 역전파 결과를 기록하는 슬롯 (mutable 상태).
  PyTorch의 zero_grad 관례도 같은 설계.
- **data (불변 — 규약일 뿐)**: Variable의 존재 이유 자체가 data 갱신 —
  step28 경사하강법 `x.data -= lr * x.grad`, step33 뉴턴 갱신이 그 증거.
  "학습 = data 갱신" (mutable이 핵심 기능). 고차 미분 맥락(32~36)에서 data가
  불변해 보이는 건 "이 그래프를 파는 동안엔 x=2 위에서 계산한다"는 **맥락의
  규약** — 언어 강제가 아님.
- **연계의 메커니즘**: `create_graph=True`로 grad가 그래프 소유 Variable이 되는
  순간, grad는 "기록 슬롯"에서 **data 세계의 일등 시민으로 승격** —
  `gx = x.grad`를 다음 계산 재료로 쓰는 것(step36)이 이 승격 덕분.
  grad 세계 → data 세계의 교차로.

### ★ 두 갈래의 수렴 — z 그래프의 DAG 본모습 (브로 관찰으로 확정)

브로: *"두 표현(y와 gx)을 합성한 새 표현도 결과적으로 원래 최초 입력 변수
참조를 만들어낸다는 것이지?"* — ✅ 정확. z = gx³+y의 그래프는 **두 갈래**:

- 갈래1: z → Pow(gx³) → gx(미분 표현의 그래프) → ... → **x**
- 갈래2: z → Add → y(원래 함수 그래프) → Square → **x** (같은 객체!)

`fill_grad(z)` 시 두 갈래의 미분 기여가 **같은 x.grad 슬롯에 합산** (step14 누적
원리) — 실증: 갈래1만 96.0 + 갈래2만 4.0 = **100** ✓.
그동안 그래프가 "한 줄(선형)"이었다면 step36에서 처음으로 **두 갈래가 같은
리프로 수렴하는 DAG**가 등장 — step15~16(복잡 그래프) + step14(누적) +
고차 미분의 합체. 그래서 머리가 꼬였던 것 (정당한 꼬임).

### ★★ 그래프의 생애 — 일회용(학습) vs 지속(고차 미분) (브로 자기 성찰로 완결)

브로: *"'data 갱신 후 완전히 새로운 계산 그래프를 다시 생성한다'는 상황이
익숙하지 않았던 것 같다"* — ★ 이것이 혼란의 마지막 뿌리. 그리고 이는
**step09 시절 혼란의 재림** (후보 6번 기록 — "만들어진 그래프에 신규 입력을
feed?" = Define-and-Run 상상. Define-by-Run의 본질: **매 입력마다 새 그래프**).

학습 루프 (step28):
```
for i in range(iters):
    y = f(x)               # 매 루프 새 그래프 생성
    fill_grad(y)
    x.data -= lr * x.grad  # data 갱신 — 기존 그래프는 버려짐 (GC)
```

| | 학습 루프 (28·33) | 고차 미분 (32~36) |
|---|---|---|
| **data** | 매 루프 갱신 (최적화 대상) | 고정 ("한 점" 규약) |
| **그래프** | **일회용** — 재생성·버려짐 | **지속** — 유지·재미분·조립 |
| Variable 상자 | 동일 객체 | 동일 객체 |

같은 프레임워크에서 그래프의 생애가 반대로 흐르는 두 모드 — 그래프는
언제나 "실행의 부산물"이며 (Define-by-Run), 그걸 한 번 쓰고 버리냐(학습)
오래 보존하며 조립하냐(고차 미분)의 차이. PyTorch도 동일 구조
(training loop마다 forward 재실행, backward 후 그래프 해제).

## 3. step36 전체 흐름 지도 — x 하나를 고정하고 보면

| 시점 | x.data | x.grad | 무슨 일 |
|---|---|---|---|
| `y = x**2` | **2** | None | y=4 계산됨 (그래프+값 동시) |
| `fill_grad(y, create_graph=True)` | **2** | **4** (y'=2x @ 2) | gx = x.grad를 뽑아 별도 보관 |
| `x.clear_grad()` | **2** | None | gx는 별도 참조로 생존 ("2x" 식) |
| `z = gx**3 + y` | **2** | None | z.data = 68 (4³+4) |
| `fill_grad(z)` | **2** | **100** (z' @ 2) | 끝! |

★ x.data=2는 **불변** — 모든 계산과 미분이 이 고정된 점 위에서 일어난다.

## 4. 헷갈림의 숨은 원인 — "몇 차 미분을 보고 있지?"

step36의 100은 **"y의 2차 미분"이 아니다** — z라는 **새 함수의 1차 미분**이다.
(z' = 24x²+2x의 24x² 항이 gx를 미분한, 즉 2차 미분 **성분**을 포함할 뿇.)

- 고차 미분 (33~35): gx를 **다시 미분** → y'' 그 자체
- 이외의 용도 (36): gx를 **조립해서 새 함수** z → z'는 z의 1차 미분

"미분 식을 재료로 만든 새 함수의 1차 미분"이 정확한 서술.

### z의 의미론 — 데모는 무의미하지만 패턴은 실무 핵심 (브로 질문에서)

브로: *"그게 딱히 어떤 의미를 가질지는 거시기하다"* — 데모의 z 자체는 맞다
(능력 시연일 뿐). 그러나 z의 **모양**(gradient를 조립한 새 함수)은 실무 핵심:

- **WGAN-GP gradient penalty**: loss에 λ(|∇D(x)| − 1)² 항 추가 — **z = gx² 모양
  그 자체**. penalty를 학습하려면 z를 또 미분 → 실무에서 create_graph=True의
  대표 사용례. "gradient 크기를 1 근처로"라는 실제 학습 목적이 담김.
- **메타러닝** (MAML류): 갱신식 w' = w − α∇L을 미분 가능 그래프로 유지 —
  gradient를 새 계산의 입력으로 쓰는 극단적 사례.
- z는 "f와 f'를 성분으로 포함한 합성 함수" (순수 함수 — 사이드이펙트가 아니라
  합성. 브로 용어 정리도 함께 기록).

## 5. 이 관점의 응용 — 재사용형(reuse_output)의 열쇠

"backward는 고정된 값을 재사용해 도함수를 평가한다"(3절)는 관점이 step35의
Config.reuse_output 이해의 열쇠이기도 하다 — 재사용형은 forward 출력 y라는
**고정된 평가값을 직접 캡처**하는 것 (tanh 재계산 생략), 재호출형은 x로부터
**다시 평가**하는 것. 같은 수학, 다른 값 조달 방식.

## 6. 실무 관점 — 왜 "한 점에서의 미분"으로 충분한가

신경망 학습도 결국 "현재 가중치 W₀라는 한 점에서의 gradient"를 얻어 갱신하는
것이다 — gradient 전체 함수가 필요 없음. Define-by-Run의 "점 평가" 특성은
제약이 아니라 실무 요구사항과 정확히 일치한다 (step28 경사하강법의 갱신 루프 회상).
