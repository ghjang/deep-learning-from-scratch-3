## 1. 자기 참조 도함수 3총사 — 흔하다

| 함수 | 도함수 | 특징 |
|---|---|---|
| **exp** | exp' = **exp** | 자기 자신과 동일 — 극단적 자기 참조 |
| **sigmoid (σ)** | σ' = **σ(1−σ)** | 신경망에서 가장 유명한 자기 참조 |
| **tanh** | tanh' = **1−tanh²** | step35 주인공 |

활성함수가 이 모양인 데엔 실무적 이유가 있다 — 5절 참조.

## 2. 미분식 성분 분류 지도 — 무엇이 등장하나

미분식에 등장하는 성분으로 함수를 분류:

| 등장 성분 | 예 | 실무적 의미 |
|---|---|---|
| **출력만** | tanh, sigmoid, exp | forward **출력** 캐시 = 역전파 재료 완결 |
| **입력만** | ReLU (x의 부호), softplus' = sigmoid(x) | forward **입력** 캐시 필요 |
| **입력+출력 동시** | **SiLU/Swish** (f' = f + σ(1−f)), ELU (구간별) | 둘 다 캐시 |
| **상수 (아무것도 안 나옴)** | Neg(−1), Add(1,1) | 캐시 불필요 — 가장 저렴 |
| **다른 입력값** | Mul의 (x₁,x₀) | 함수 인자축의 등장 (데이터축과 직교) |

★ 활성함수 전통이 "출력형"인 이유: **미분이 출력의 함수 = 순전파 값만 저장하면
역전파를 즉시 계산** 가능 — 메모리·계산 효율. 프레임워크가 activation의 forward
출력을 저장해두는 이유.

## 3. 그래프 3형태 — 미분 반복의 운명 (step35 실증)

| 형태 | 대표 | 수학적 이유 | step35 실측 |
|---|---|---|---|
| **소멸** | 다항식 (x⁴→…→상수→0) | 차수 감소. 도함수가 상수가 되면 x로 가는 간선 소멸 → 재미분 결과가 **0이 아니라 None** (연결 없음, dezero 동일) | - |
| **순환** | sin | 4주기 (sin→cos→−sin→−cos) — 그래프 크기 일정 | step34: 4곡선 phase shift |
| **폭증** | tanh | 자기 참조가 미분마다 복제 | Tanh **2→4→8→16→32** (2배), Function 10→29→87→261→791 (≈3배) |

★ 폭증의 실측 규칙 (step35 데모 4): tanh 참조가 미분마다 복제되므로 Tanh는
2^n개. **8차는 노드 수만 개 — dot 렌더링조차 수 분** (M5 Max에서 중단).
"폭증의 진짜 의미는 렌더링조차 무거워지는 것" — 책이 시각화를 아껴 쓴 이유.

## 4. exp의 특이성 — 자기 참조인데 안 클 수도

exp' = exp는 자기 참조인데 **식이 전혀 안 커진다** (미분해도 그냥 exp).
그런데 그래프 크기는 구현 방식에 달렸다:

- dezero식 (y 재사용): exp 노드 1개 유지 — 미분해도 크기 불볕
- rezero식 (exp 재사용): 매 미분마다 Exp 노드 추가 — 폭증

→ **수학적 특성(자기 참조)과 구현 방식(재사용/재호출)은 직교하는 축**.

## 5. ★ rezero vs dezero — 미분식 구현의 두 길 (브로 분석 인용)

Tanh backward를 나란히:

```python
# dezero — backward가 "출력"에 접근                  # rezero — derivative가 "입력"만 받음
def backward(self, gy):                              def derivative(self):
    y = self.outputs[0]()  # forward 출력 재사용          return lambda x: 1 - tanh(x) ** 2
    gx = gy * (1 - y * y)  # y*y — Tanh 노드 재사용            # tanh(x) 재호출 — 새 노드
```

- **근본**: dezero의 Function은 자기 출력(self.outputs, weakref)에 접근 가능.
  rezero derivative hook은 "입력 x → 도함수" 순수 설계라 **출력 접근 창구가 없음**
  (Neg 버그와 같은 뿌리 — hook 설계의 특징이 낳은 결과).
- **★ 브로 분석 (2026-08-24, 자가 도달)**:
  - dezero: "곱셈노드 1개, 입력은 1개 재사용 1개 노드" — mul(y,y) 1개 + 기존
    Tanh₁ 재사용 → **Tanh 박스는 영원히 1개**
  - rezero: "tanh와 pow 노드 2개가 파이프라인" — tanh(x)→**2 의 Tanh·Pow 2노드가
    매 미분마다 추가 → 폭증
  - 평가: **"계산 이득은 DeZero가 더 있을 것"** (tanh 값 재계산 없음 — 캐시 효과)
    / **"수학적 이해의 이득은 리제로가 약간 더"** (도함수 식이 그래프에
    self-contained로 명시 — 무엇을 계산 중인지 읽힘)
- 둘 다 정확한 평가. 정답지(dezero) 방식이 실무 최적이지만, 교육 관점에서 rezero
  방식의 명시성은 버릴 것 없음 — **이해와 효율은 다른 축**.

### ★★ 후속 실험 — rezero에서도 재사용형이 된다 (브로 지적에서 도출, 같은 날)

브로 질문: *"rezero에도 self.output이 있는데 참조 안 한 건 람다에서 불가여서?"* —
**불가가 아니라 안 그렇게 썼을 뿐**이었다. 클로저 캡처로 가능:

```python
def derivative(self):
    y = self.output()              # forward 출력 재사용 — 브로 발견
    return lambda _: 1 - y * y
```

실증 (Tanh 노드 수, 재미분 1/2/3회):

| 방식 | Tanh 수 | Function 총계 |
|---|---|---|
| 재호출형 (rezero 현재) | 2 → 4 → 8 (지수 폭증) | 10 → 29 → 87 |
| **재사용형 (self.output 캡처)** | **1 → 1 → 1 (불변!)** | 9 → 23 → 63 |

- 재사용형은 미분 그래프가 기존 y → Tanh₁ → x 체인을 경유 — Tanh 박스 1개 유지
- 안 썼던 이유: (a) derivative hook 관습 — "도함수는 입력의 순수 함수"로 표현,
  (b) v1 도함수가 전부 입력형이었음 (tanh가 첫 출력형) — 습관대로 재호출로 작성
- 교훈: **hook 설계가 금지하는 게 아니라 관습이 안 쓰고 있었던 것** — 인터페이스의
  표현력은 실제로 쓰기 전까지 과소평가되기 쉽다
- ★ **단독 사용 가능성의 차이** (브로 질문 "함수 클래스만 자체적으로 사용?"):
  재호출형은 `Tanh().derivative()`만으로 **도함수 객체를 단독 획득** — 순전파/
  fill_grad 없이 `df(x)`로 즉시 미분값 (실증: f'(1)=0.41997, Square 6.0).
  "f'도 값이다"(일급 함수 — 탐구 노트 13, 항목 013)의 실현. 재사용형은
  self.output 캡처에 의존해 **순전파 없이는 도함수가 존재 못 함** (AssertionError)
  — 효율의 대가로 도함수의 순수성(단독 존재성)을 내놓은 것.
- ★ **Config 전역 옵션으로 구현에 반영** (브로 제안 — 인스턴스 옵션 제안 후
  "Config 쪽이 낫지 않을까"로 재제안, 채택): `Config.reuse_output` + 
  `using_config('reuse_output', True)` 블록. ★ 미묘한 디테일: derivative는
  **역전파(fill_grad) 중 호출**되므로 블록이 fill_grad를 감싸야 효과가 있음
  (순전파 시점 아님) — "미분 그래프 구축 방식"의 스위치치고 논리적으로 정확한 위치.
  step18 철학("역전파 동작 전환은 Config 스위치")과 일관됨.
  초안은 인스턴스 옵션 `Tanh(reuse_output=...)`였으나 wrapper 시그니처 오염 +
  신경망 전체 적용 시 인자 전파 문제로 Config 방식으로 전환 — 설계 변천 기록.
