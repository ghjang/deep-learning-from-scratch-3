<a id="한장요약"></a>
## 0. 한 장 요약 — 전치 = 서류 재철

> **고차원 전치는 그림이 아니라 절차다. "첫 축이 무엇인가" = "무엇으로 묶었는가". 전치 = 묶음 기준의 교체. 데이터는 언제나 무동.**

| 배치 | 첫(바깥) 축 | 배열 읽기 |
|---|---|---|
| **NCHW** | N (이미지) | "이미지별로 — 각 이미지 안에 채널 순서로" |
| **CNHW** | C (채널) | "채널별로 — 각 채널 안에 이미지 순서로" |
| **NHWC** | N (이미지) | "이미지별로 — 각 이미지 안에 픽셀(H,W)이 먼저, 채널이 안쪽" |

- ★ 4D+의 전치를 "그리려" 하면 막힌다 (노트 37 §1 concept image) — 대신 **절차**: ① 이름표 → ② 첫 축이 뭔지 묻기 → ③ shape 검증 (노트 37 §2 프로토콜의 고차원 확장)
- 이 노트의 루틴: **예측 → numpy로 검증**. 국어로 확신 얻으려 하지 말 것

<a id="창고비유"></a>
## 1. 직감 펌프 — 창고 비유

같은 서류 24장(데이터 = 버퍼)을:

- **"고객별 폴더"** 에 꽂아두다가 (N 바깥 — 각 폴더에 그 고객의 전체 서류)
- **"항목별 폴더"** 로 재철한다 (C 바깥 — 각 폴더에 모든 고객의 그 항목)

이때 **서류는 한 장도 안 바뀌고, 꽂힌 순서(메모리)도 안 바뀐다** — 교체되는 건 색인지(어드레싱)뿐. 전치 후 `b[0]`를 열면 "폴더 0"이 가리키는 서류 묶음이 다를 뿐. **같은 창고, 다른 분류 체계.**

<a id="4d기본기"></a>
## 2. 4D 기본기 — (2,3,2,2)를 손으로

```python
import numpy as np

a = np.arange(24).reshape(2, 3, 2, 2)      # (N=2, C=3, H=2, W=2)
# 이름표: (이미지, 채널, 세로, 가로)

a[0]        # 이미지 0 전체 (3, 2, 2):
            #   R 평면 [[0, 1], [2, 3]]
            #   G 평면 [[4, 5], [6, 7]]
            #   B 평면 [[8, 9], [10, 11]]
            #   ← "이미지별 묶음" — 폴더를 열면 한 이미지의 R,G,B가 나옴

b = a.transpose(1, 0, 2, 3)                # (C=3, N=2, H=2, W=2)
b[0]        # 채널 R 전체 (2, 2, 2):
            #   이미지 0의 R [[0, 1], [2, 3]]
            #   이미지 1의 R [[12, 13], [14, 15]]
            #   ← "채널별 묶음" — 폴더를 열면 모든 이미지의 R만 나옴

# 검증 (인덱스 대응: b[c, n, h, w] = a[n, c, h, w])
b[0, 1, 0, 0] == a[1, 0, 0, 0] == 12      # True
```

- 트리로: (N,C,H,W)는 N층이 루트 ↔ (C,N,H,W)는 C층이 루트 — **층의 순서만 교환** (노트 37 §2 트리 뷰). 잎(스칼라)과 버퍼는 무동
- 손 루틴: `transpose(1, 0, 2, 3)`를 보면 → "새 첫 축 = 옛 축1(C)" → "이제 C가 묶음 기준" 구나, 끝

## 3. 연습 문제 — Level 1~4

> 방식: 먼저 손으로(머리로) 예측 → 그 후 실제 numpy로 채점. **국어 대신 shape와 print**

### Level 1 — 축 읽기

- Q1. `np.zeros((4, 3, 8, 8))` — 각 축에 역할 이름을 붙여라 (정답 없음 — 단, 하나 제안: (N=4, C=3, H=8, W=8)). 첫 축이 바깥 = 무엇으로 묶였나?
- Q2. 위 배열에서 `x[2]`를 열면 무엇이 나오나? shape는?

### Level 2 — 전치 후 묶음 예측

- Q3. (2, 3, 2, 2)에 `transpose(0, 3, 1, 2)` — 결과 shape는? 새 첫 축(묶음 기준)은 무엇?
- Q4. `transpose(3, 2, 1, 0)` (전축 역순 — 4D의 `.T`) — shape와 묶음 기준은?

### Level 3 — 역방향 설계 (원하는 묶음 → axes)

- Q5. NHWC (N, H, W, C)를 NCHW로 바꾸는 axes는?
- Q6. 어텐션 텐서 (B, S, H, D)를 (B, H, S, D)로 (헤드를 앞으로) — axes는?
- Q7. 채널별 통계(BatchNorm 준비)를 위해 **채널을 바깥으로 당기는** axes는? (당기기!)

### Level 4 — 도전 (5D)

- Q8. 비디오 (N, T, C, H, W)에서 "프레임별(T) 우선"으로 보고 싶다 — axes는? 결과 shape는?

### 정답·검증

# Q3: (2, 2, 3, 2) — 첫 축 = 옛 축0(N) 그대로, 그 안에서 (W, C, H) 순
# Q4: (2, 2, 3, 2) — 첫 축 = 옛 축3(W): "가로줄 우선" 묶음 (의미상 거의 안 씀 — 역순 전치는 실수로 하는 경우가 많아 주의)

## 4. 5D·6D·7D+ — 큐브 배치도의 재귀와 잎 선택 자유

- 5D 비디오 (N, T, C, H, W) = **4D 큐브(비디오)의 나열** — 큐브 배치도 원칙(노트 37 §8)의 한 단계 위
- 재귀: 6D = 큐브의 3D 격자, 7D = "큐브 격자들의 나열" 또는 "4D 격자 속 큐브" — 배치 축이 늘어날 뿐, 잎은 여전히 3D 큐브
- ★ **잎 선택의 자유** (2026-08-30 브로 관찰: *"7D 이상은 6차원 초고차 큐브의 일렬 나열?"*): 배치도의 잎이 꼭 3D일 필요 없음 — 7D를 "6D 하이퍼큐브의 1D 나열"로 봐도 전부 정당한 분해. 이 자유는 트리 분해의 자유(노트 37 §2)·텐서곱 결합(노트 38 §2.4)과 같은 이야기 — **분해는 진리가 아니라 선택**
- 실전 5D: Conv3D 입력 (B, C, T, H, W), 비디오 트랜스포머의 패치 임베딩

## 5. 회수 지도 — 이 노트가 쓰일 곳

| 시점 | 회수 내용 |
|---|---|
| **step38** (reshape/transpose 미분) | 이 노트의 Level 1~3이 직접 무기 — "구조 연산도 미분 가능"을 손으로 아는 상태로 시작 |
